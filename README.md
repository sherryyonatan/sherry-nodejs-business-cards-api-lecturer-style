# Business Cards REST API

## אודות הפרויקט

פרויקט גמר בקורס Node.js.

הפרויקט הוא שרת REST API לניהול משתמשים וכרטיסי ביקור עסקיים. המערכת
מאפשרת הרשמת משתמשים, התחברות, ניהול משתמשים, יצירה וניהול של כרטיסי
ביקור, סימון כרטיסים ב-Like וניהול הרשאות לפי סוג המשתמש.

השרת נבנה באמצעות Node.js ו-Express, ועובד מול MongoDB באמצעות Mongoose.

## Users API

### הרשמת משתמש

`POST /users`

פתוח לכולם. כתובת האימייל חייבת להיות ייחודית.

### התחברות

`POST /users/login`

מבצע אימות של כתובת האימייל והסיסמה ומחזיר JWT במקרה של התחברות מוצלחת.

### קבלת כל המשתמשים

`GET /users`

הרשאה: Admin בלבד.

### קבלת משתמש לפי ID

`GET /users/:id`

הרשאה: המשתמש עצמו או Admin.

### עריכת משתמש

`PUT /users/:id`

הרשאה: המשתמש עצמו.

### שינוי סטטוס Business

`PATCH /users/:id`

מאפשר למשתמש לשנות את ערך `isBusiness` שלו.

### מחיקת משתמש

`DELETE /users/:id`

הרשאה: המשתמש עצמו או Admin.

------------------------------------------------------------------------

## Cards API

### קבלת כל הכרטיסים

`GET /cards`

פתוח לכולם.

### קבלת הכרטיסים של המשתמש המחובר

`GET /cards/my-cards`

דורש משתמש מחובר.

### קבלת כרטיס לפי ID

`GET /cards/:id`

פתוח לכולם.

### יצירת כרטיס

`POST /cards`

הרשאה: משתמש עסקי בלבד.

### עריכת כרטיס

`PUT /cards/:id`

רק המשתמש שיצר את הכרטיס רשאי לערוך אותו.

### Like / Unlike

`PATCH /cards/:id`

משתמש רשום יכול להוסיף או להסיר Like מכרטיס.

### מחיקת כרטיס

`DELETE /cards/:id`

הרשאה: יוצר הכרטיס או Admin.

------------------------------------------------------------------------

## Authentication & Authorization

המערכת משתמשת ב-JSON Web Token לצורך אימות והרשאות.

ה-JWT כולל:

-   `_id`
-   `isBusiness`
-   `isAdmin`

נתיבי API מוגנים משתמשים ב-Authorization Header לצורך אימות המשתמש.

סיסמאות אינן נשמרות כטקסט רגיל והן עוברות Hash באמצעות `bcryptjs` לפני
השמירה במסד הנתונים.

------------------------------------------------------------------------

## Validation

נתוני המשתמשים והכרטיסים עוברים ולידציה באמצעות Joi לפני השמירה במסד
הנתונים.

בקשות שאינן עומדות בדרישות הוולידציה מוחזרות עם HTTP Status מתאים.

------------------------------------------------------------------------

## קודי HTTP וטיפול בשגיאות

השרת משתמש בקודי HTTP מתאימים, לדוגמה:

-   `200` -- הבקשה הצליחה
-   `201` -- משאב נוצר בהצלחה
-   `400` -- בקשה או נתונים לא תקינים
-   `401` -- משתמש לא מאומת
-   `403` -- אין הרשאה מתאימה
-   `404` -- המשאב לא נמצא
-   `500` -- שגיאת שרת

מזהי MongoDB לא תקינים מטופלים ומחזירים `400`.

## תכונות בונוס

### שינוי bizNumber על ידי Admin

נוסף נתיב המאפשר ל-Admin לשנות את ה-`bizNumber` של כרטיס קיים:

`PATCH /cards/:id/biz-number`

המערכת בודקת שהמשתמש הוא Admin ושהמספר החדש אינו משויך לכרטיס אחר.

### שמירת שגיאות בקובץ Log

בקשות המסתיימות ב-HTTP Status של `400` ומעלה נשמרות גם בקובץ Log.

קבצי ה-Log נוצרים בתיקיית:

`logs/`

התיקייה אינה מיועדת להעלאה ל-Git.
